# AI 生图 SaaS MVP 设计文档

日期：2026-05-14

## 概要

构建一个可部署的 AI 生图 SaaS MVP。产品目标是帮助用户在不从零编写完整提示词的情况下，生成更稳定、更专业的图片。用户必须提供主体描述，也可以选择图片类型、画面比例、风格、场景、留白/构图要求、参考图和补充要求。系统会把这些输入组装成结构化提示词，并调用 OpenAI GPT Image API 生成图片。

网站默认使用中文界面，并提供英文切换选项。MVP 面向海外/全球部署，技术栈使用 Next.js、Vercel、Supabase 和 OpenAI。

## 目标

- 提供完整的第一版 SaaS 流程：首页、登录注册、生图、历史记录、积分和升级入口。
- 每个新用户赠送 2 个免费积分。
- 每成功生成 1 张图片消耗 1 个积分。
- 积分不足时显示升级提示。
- 将生成图和可选参考图保存到 Supabase 私有 Storage。
- 用户只填写主体也能生成图片，同时提供可选控制项来提升输出质量。
- 实际提交给 OpenAI 的提示词尽量保留用户原始输入语言，不强制翻译成英文。

## 非目标

- 真实支付集成。
- 邮箱验证、找回密码或邮件通知。
- 后台管理系统。
- 博客系统或复杂 SEO。
- 完整图片编辑器、蒙版、局部重绘界面、物体移除或本地图片编辑。
- 多图片模型切换。
- 单次生成使用多张参考图。
- 异步任务队列和高级任务面板。

原始范围排除了参考图上传。最新确认范围加入了 1 张可选参考图，并按下文约束实现。

## 推荐架构

使用 Next.js 全栈单体架构：

- Next.js App Router 负责页面、布局、Route Handlers 和 middleware。
- Supabase Auth 负责邮箱/密码登录注册。
- Supabase Postgres 保存用户资料、积分和生成记录。
- Supabase Storage 保存私有参考图和生成图。
- OpenAI Images API 负责文本生图和基于参考图的生成/编辑。
- Vercel 负责部署。

这样可以让 MVP 部署和维护尽量简单。生成队列、后台任务、支付和管理工具可以等流量或产品需求明确后再拆分。

## 页面

### `/`

首页。默认用中文说明产品价值，展示简洁的生成流程，并提供清晰操作入口：

- 开始生成。
- 登录 / 注册。
- 升级入口。

第一版不做复杂 SEO、博客或营销 CMS。

### `/login`

使用 Supabase Auth 实现邮箱/密码登录和注册。

第一版不实现邮箱验证、找回密码或邮件通知。注册成功后，系统创建用户 profile，并赠送 2 个积分。

### `/create`

核心引导式生图页面。

必填输入：

- 主体：用户想生成的核心内容。

可选输入：

- 图片类型：通用、海报、社媒封面、商品图、插画、头像、横幅等预设。
- 画面比例：`1:1`、`4:5`、`16:9`、`9:16`、`3:2`。
- 风格：真实摄影、极简、3D、插画、电影感、水彩、赛博朋克等预设。
- 场景：室内、户外、工作室、自然、城市、节日、电商棚拍等预设。
- 留白/构图：无特殊要求、顶部留白、底部留白、左侧留白、右侧留白、主体居中。
- 参考图：可选上传 1 张图片。
- 补充要求：自由文本。

画面比例控件必须同时展示数字比例和小预览图标。图标要直观表达正方形、竖版、横版或宽屏构图。组件应使用稳定尺寸，避免标签或图标导致布局跳动。

提示词预览默认折叠，但应允许用户展开查看，提高透明度。预览应包含：

- 中文预览：用中文解释系统组装后的提示词，方便用户理解。
- 英文参考预览：提供英文版本，方便需要检查英文表达的用户查看。
- 实际提交内容：后端最终会提交给 OpenAI 的精确提示词文本，默认保留用户原始输入语言。

如果界面语言是中文，中文内容优先展示。如果界面语言是英文，英文内容优先展示。实际提交内容必须明确标注，让用户知道最终发送的是什么。

### `/history`

按时间倒序展示当前用户的生成历史。

每条记录展示：

- 生成图预览。
- 创建时间。
- 状态。
- 参数摘要。
- 是否使用参考图。
- 成功图片的下载操作。

失败记录可以显示错误状态，但页面重点应放在成功生成的图片输出上。

### `/upgrade`

升级占位页。

展示未来套餐入口，并明确显示“支付即将上线”状态。第一版不实现真实 checkout 或订阅逻辑。

积分不足弹窗会引导用户进入该页面。

## 语言策略

网站默认使用中文。用户可以切换到英文。

语言偏好：

- 先保存在浏览器中，适用于所有用户。
- 为登录用户增加 `profiles.locale` 字段，方便后续在服务端持久化该设置。

提示词行为：

- 不强制把用户提供的主体和补充要求翻译成英文。
- 保留中文、英文或中英混写的用户输入。
- 结构化提示词字段默认跟随当前界面语言生成。
- 画面比例等技术参数必须清晰、明确，避免歧义。
- 英文优化作为未来可选模式，不作为 v1 默认行为。

这样可以降低自动翻译导致语义偏移的风险，让用户意图更贴近实际 API 调用。

## 参考图范围

参考图上传是可选功能。

MVP 约束：

- 最多 1 张参考图。
- 支持格式：JPEG、PNG、WebP。
- 前端文件大小限制：10 MB。
- 显示缩略图预览和移除按钮。
- 通过 Supabase 私有 Storage 保存通过校验的参考图。
- 不支持多图混合、蒙版、局部重绘界面、背景移除或本地编辑工具。

如果没有上传参考图，后端使用普通文本生图流程。如果上传了参考图，后端使用支持图片输入/参考图/编辑行为的 OpenAI 图片接口，并配合配置好的 GPT Image 模型。

## 积分规则

- 新注册用户获得 2 个积分。
- 每成功生成 1 张图片消耗 1 个积分。
- 如果用户积分为 0，`/api/generate` 在调用 OpenAI 前直接返回积分不足错误。
- OpenAI 调用失败不消耗积分。
- 如果在调用 OpenAI 前已经预留或扣除了积分，但调用失败，系统要在积分流水中记录退款。
- 积分操作必须具备原子性，避免并发请求把余额扣成负数。

## 数据模型

### `profiles`

每个 Supabase Auth 用户对应一行。

字段：

- `user_id` UUID 主键，引用 `auth.users`。
- `email` text。
- `credit_balance` integer，默认 `2`。
- `locale` text，默认 `zh`。
- `created_at` timestamptz。
- `updated_at` timestamptz。

### `credit_ledger`

追加式积分流水表。

字段：

- `id` UUID 主键。
- `user_id` UUID。
- `amount` integer。赠送/退款为正数，消耗为负数。
- `reason` text，例如 `signup_bonus`、`generation_debit`、`generation_refund`、`manual_adjustment`、`future_purchase`。
- `generation_id` UUID，可为空。
- `created_at` timestamptz。

### `generations`

每次生成尝试对应一行。

字段：

- `id` UUID 主键。
- `user_id` UUID。
- `status` text：`processing`、`succeeded` 或 `failed`。
- `subject` text。
- `image_type` text，可为空。
- `aspect_ratio` text，可为空。
- `style` text，可为空。
- `scene` text，可为空。
- `whitespace` text，可为空。
- `additional_requirements` text，可为空。
- `locale` text。
- `prompt_preview_zh` text，可为空。
- `prompt_preview_en` text，可为空。
- `submitted_prompt` text。
- `reference_image_path` text，可为空。
- `generated_image_path` text，可为空。
- `error_message` text，可为空。
- `created_at` timestamptz。
- `updated_at` timestamptz。

### Storage Buckets

- `reference-images`：私有桶，用于保存上传的参考图。
- `generated-images`：私有桶，用于保存生成结果。

历史记录页面应使用短期 signed URL 展示图片，不能直接暴露私有 Storage 路径。

## 后端 API

### `POST /api/generate`

职责：

1. 校验 Supabase session。
2. 校验主体是否存在。
3. 校验可选字段和补充要求长度。
4. 校验可选参考图格式、数量和大小。
5. 创建提示词预览和实际提交提示词。
6. 原子性预留或扣除 1 个积分，并创建 `processing` 生成记录。
7. 如果提供参考图，将参考图上传到私有 Storage。
8. 调用 OpenAI Images API：
   - 无参考图：文本生图。
   - 有参考图：图片输入/参考图/编辑流程。
9. 将生成结果保存到私有 Storage。
10. 将生成记录标记为 `succeeded`。
11. 失败时，将生成记录标记为 `failed`，并退回任何已预留或已扣除的积分。

后端不能信任客户端组装的提示词。客户端预览只用于展示；最终提示词必须由服务端代码重新组装。

### `GET /api/generations`

返回当前用户的生成记录，并附带图片 signed URL。

### `GET /api/credits`

返回当前用户的积分余额。

### Auth Callback 和 Middleware

使用 Supabase 推荐的 Next.js middleware/session 模式。受保护路由包括 `/create` 和 `/history`。

## 提示词组装

提示词构建器接收结构化输入，并返回：

- `promptPreviewZh`。
- `promptPreviewEn`。
- `submittedPrompt`。

默认行为：

- 主体必填，并保留原始语言。
- 未选择图片类型时，默认为通用高质量图片。
- 未选择画面比例时，默认 `1:1`。
- 未选择风格时，默认清晰、高质量、有视觉吸引力。
- 未选择场景时，不额外添加场景限制。
- 未选择留白要求时，不额外添加构图限制。
- 未填写补充要求时，不添加额外自由文本段落。
- 有参考图时，追加“使用上传图片作为视觉参考，同时遵守提示词”的说明。

实际提交提示词应结构化且明确。中文界面下，提交中文提示词是可接受且预期的；英文界面下，提交英文提示词也是可接受的。默认不应机器翻译用户提供的内容。

## 错误处理

用户可见错误应简洁：

- 未登录：跳转登录页。
- 主体缺失：提示用户输入主体。
- 参考图无效：说明允许格式和大小限制。
- 积分不足：显示升级弹窗。
- 生成失败：显示适合重试的错误提示，并且不消耗积分。

服务端日志应保留足够调试信息，但不能泄露 API Key 或私有 signed URL。

## 安全与隐私

- 所有业务表开启 Row Level Security。
- 用户只能读取自己的 profile、积分流水和生成记录。
- Storage 桶为私有。
- Signed URL 应短期有效。
- OpenAI API Key 和 Supabase service role key 只能在服务端使用。
- 文件上传必须在写入 Storage 和调用 OpenAI 前完成校验。

## 测试计划

覆盖以下场景：

- 未登录用户访问 `/create` 和 `/history` 会被重定向到登录页。
- 新用户注册后创建 profile，并获得 2 个积分。
- 只填写主体即可生成。
- 可选字段全部为空时不阻塞生成。
- 画面比例选择器在桌面端和移动端都显示数字标签和预览图标。
- 参考图上传只接受 1 张符合大小限制的 JPEG、PNG 或 WebP。
- 积分不足时阻止 OpenAI 调用，并显示升级提示。
- 生成成功后准确扣除 1 个积分，并创建历史记录。
- 生成失败时退回或保留积分，并记录失败状态。
- 历史页只显示当前用户自己的记录。
- UI 默认中文，并且可以切换到英文。
- 提示词预览显示中文、英文参考和实际提交内容。
- 后端默认提交保留用户输入语言的提示词。

## 环境变量

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `OPENAI_API_KEY`
- `OPENAI_IMAGE_MODEL`
- `NEXT_PUBLIC_APP_URL`

`OPENAI_IMAGE_MODEL` 应在实现时默认使用当前账号可用的 GPT Image 模型。把模型名做成可配置项，可以避免在 OpenAI 可用性变化时把模型名硬编码在代码里。

## 实施说明

- v1 使用本地字典文件管理中文和英文 UI 文案。
- 用独立的 `AspectRatioOption` 组件实现带图标的比例按钮。
- 使用 server-only 提示词构建器生成最终提交提示词。
- 使用数据库函数或事务安全 SQL 处理积分扣减和退款。
- v1 不接入支付，但积分流水的 reason 要兼容未来购买记录。
- 参考图逻辑要保持隔离，方便未来加入多参考图或编辑功能时不重写主表单。
